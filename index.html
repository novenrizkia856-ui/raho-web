WHY AGENTS NEED A FIREWALL

Two ways to hand an agent a wallet. Both break.

Route AGive it the keys

One bad output is final

A confused or manipulated agent can move anything. Onchain, there is no undo.

Nothing is limited

Every asset, every contract, every amount. The key does not know what the task was.

You only see the damage

The chain records what happened. Nobody recorded what the agent tried, or why.

Route BSign everything yourself

The agent waits on you

Every routine payment needs your click. The autonomy you wanted is gone.

Fatigue wins

After the hundredth prompt, people approve without reading. That is when it goes wrong.

There are still no rules

A tired click is not a policy. Nothing stops the next mistake by design.

One cause on both sides:
nobody wrote down what the agent may do.

SESSIONS

The agent gets a session.
It never gets your keys.

2:00:00
RESEARCH AGENT · ACTIVE · USDC ONLY · $100 MAX · EXPIRES IN 2 HOURS

Scoped

Only the assets and contracts you list, for the task in front of it.

Capped

A spending ceiling for the whole session, not just each request.

Expiring

When time is up, every new request blocks. Only an active session can allow.

EMERGENCY CONTROLS

You can stop the agent. It cannot stop you.

Pause Agent

New requests from that agent are blocked. Everything else keeps running.

Revoke Session

Its current authority ends now. A new session is needed before it can act.

Emergency Lock

Every agent is blocked at once. It overrides every allow rule and session.

Reset Limits

Conservative defaults come back after anything unusual. The agent cannot undo any of this.
